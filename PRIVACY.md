# Privacy Policy

Last updated: November 25, 2026

Dialogue Export does not upload conversations to its developer or to third-party services.

Conversation content is collected for export only after the user starts an export. Processing occurs locally inside Firefox, and the resulting file is saved directly through Firefox's download or print interface. Opening export controls reads the current conversation title, provider and message count to prepare the interface. The compact page widget also measures visible element boundaries locally to avoid overlapping the chat; this makes no network requests.

The extension does not include analytics, telemetry, advertising, tracking, remote scripts, user accounts, or external servers. Local preferences store export options, including which image categories to include.

Version 0.5.6 adds a separate ChatGPT history archive. Opening its local extension tab makes no history request. **Load list** explicitly requests conversation IDs, titles and list metadata from ChatGPT, including the archived list if selected. **Export selected** then requests only those selected conversation IDs, sequentially. These are authenticated GET requests to ChatGPT using the session of the source tab; no account data is sent to the developer. Session tokens remain in memory in the content script, never enter extension messages or downloaded archives, and are discarded when the operation ends. The archive tab's commands are bound to its source tab and cannot be issued by website pages.

The history archive stores its list, report metadata and one bounded ZIP buffer in extension memory. The archive does not persist these to IndexedDB or resume them after restart. Completed ZIP parts and reports are saved through Firefox Downloads. Archives and reports intentionally contain selected chat titles, IDs and filenames; reports identify confirmed downloads, failures and unattempted chats. Closing the archive tab stops its operation and discards in-memory state, while already downloaded files remain. Closing/reloading the source tab can interrupt the reader; already prepared chats are then saved when downloading remains available. Explicit Stop cancels unsaved work. Failed-chat explanations use fixed categories and do not forward arbitrary exception text. The local UI shows up to 20 failed titles and codes; the JSON report retains all rows. The history archive includes text only: it makes no image download requests. The existing single-conversation image options apply to single-conversation export, not this archive mode.

Version 0.5.6 adds an optional completion/error notification preference, off by default. Enabling it requests the optional Firefox `notifications` permission. Alerts use Firefox's operating-system notification mechanism and contain only the extension name, generic result and part count, with no conversation title, text, URL, filename or raw error details. Notification delivery does not send export content to the developer. The permission is not required for export or the in-tab status.

The compact menu embeds the extension's own local interface on ChatGPT/Gemini pages. Only that interface HTML and its dialogue/archive icons are exposed as web-accessible resources for those sites; export data and temporary parts are not exposed. Its commands pass through the extension background and are bound to the containing tab. The ChatGPT-page ZIP command only opens the archive interface; history is still requested only after Load list. First-time notification permission can be enabled from a separate local extension settings tab; that page does not receive conversation data.

Version 0.5.8 uses the `scripting` permission to restore its own bundled content scripts and styles when its open export controls find that the selected ChatGPT/Gemini tab has no extension receiver (for example, a tab opened before installation). Only the extension's controls can request this action, and only the top frame of those existing supported sites is eligible. It does not inject remote code or start an export. While the controls are open, local status checks retry after page loading or a temporary disconnect. A responding or busy script is not reinitialized. Site permissions still apply; no additional hosts are requested.

For large direct ChatGPT HTML/PDF exports, version 0.5.6 stages numbered parts temporarily in the extension's local IndexedDB storage instead of retaining all embedded images in RAM. These temporary parts contain conversation content and embedded images, not the session access token. HTML parts are removed from temporary storage after their downloads complete. PDF parts stay available for switching in the print page and are removed when that page closes. In 0.5.8, Stop and image-embedding errors retain complete messages while the user chooses **Save collected** or **Discard**; the current completed buffer may also remain in the source tab's memory. Saving makes a visibly marked partial export. Discard, source-page closure/navigation and unrecoverable preparation/storage failures trigger cleanup. Abandoned jobs expire after one hour of inactivity and are removed when storage is next accessed or the extension background starts; this is not an exact one-hour deletion guarantee while Firefox is closed. Completed downloaded files are not deleted by this cleanup. No staged content is uploaded.

Dialogue Export requests access to `https://chatgpt.com/*` and `https://gemini.google.com/*` so it can read the open conversation selected by the user. Version 0.5.7 also requests `https://images.openai.com/*` to embed ChatGPT's referenced image previews. No content script is installed on the image host.

For explicit supported OpenAI preview URLs in the normalized direct HTML/PDF image list, version 0.5.8 checks existing host permission before resolving file download links, downloading images or staging parts. This check is local, cancellable and bounded by a five-second deadline. If Firefox has not granted image-host access, export offers an **Allow image access** button. It opens a local extension page that requests only `https://images.openai.com/*` after another explicit click; it does not receive conversation data or restart export automatically. Image failure diagnostics contain fixed error codes, dimensions and, when available, a numeric HTTP status, not image URLs, text, cookies or tokens.

In 0.5.8, direct exports may retry the same referenced image up to three attempts for temporary network/HTTP failures, requesting a fresh ChatGPT download link when available. No new image searches or additional hosts are introduced. Diagnostics also include fixed request-stage/reference categories, attempt count, bounded received-byte count and the message position. Copy diagnostic requires a click; these reports are not uploaded or written to persistent diagnostic storage.

Direct-reference failure diagnostics contain only fixed type categories, field presence and numeric counts. Unknown type values, marker payloads, conversation text, URLs and identifiers are excluded. These reports stay in the conversation tab's memory until the next export or page reload; the export menu can display them after the transient error notice disappears. **Copy diagnostic** copies the displayed report only after a click. There is no automatic upload.

For **All → TXT/Markdown/HTML/PDF/JSON** in saved ChatGPT conversations, the extension can request the current session and the current conversation directly from `chatgpt.com` after the user starts export. These authenticated GET requests use the user's existing ChatGPT session; no API key is requested. A session access token is used only in memory during the export and is never logged, stored in preferences, sent to another origin, or included in the export. Conversation data is processed locally. Conversation responses are not cached by the extension, and export stops if the conversation changes. Version 0.5.8 stops unsupported saved-chat exports instead of automatically scrolling the page. Already loaded card nodes may be used after checking their exact message identities and branch order.

Version 0.5.8 renders supported static card layouts locally from saved component text. Its bounded parser interprets literals, property access, arithmetic, conditional expressions and repeated rows; it does not execute JavaScript, event handlers or page functions from a message. Image queries are matched only to exact saved references; the extension does not perform new image searches. Missing citation links are marked explicitly. When Working / Thinking is enabled, available saved thought summaries and assistant progress updates are attached to their response; hidden records, raw tool output, analysis-channel text and service recap records are excluded. No additional requests are made to retrieve activity.

Direct HTML/PDF export can also request image download links from ChatGPT and download image bytes referenced by the current conversation. Cross-origin image requests omit cookies, the ChatGPT authorization token and the referrer; no conversation text is uploaded to image hosts. Supported image bytes are embedded in the output and temporary image data is released after preparation. The locally bundled Markdown parser does not execute raw HTML supplied in messages. No runtime CDN scripts are used. Download availability and browser CORS rules can prevent image embedding; in that case the direct export stops rather than silently omitting an image.

When **Include message timestamps** is enabled for ChatGPT, the extension reads message IDs and creation times from the direct conversation response or, during page collection, metadata already present on the conversation page. No separate timestamp request is made. The preference is stored locally, and timestamp data is kept in memory during collection.

During HTML/PDF page collection, existing lazy images in mounted messages may temporarily be set to load eagerly so Firefox can finish loading them before capture. These are the image URLs already used by the conversation page; the extension does not upload the content or use a separate media-fetching service. In version 0.5.7, the extension background can make bounded GET requests for referenced previews at `images.openai.com/static-rsc-*/` or `images.openai.com/thumbnails/`, because the page may display these images without being allowed to read their pixels. The unsigned 0.5.8 uses this same reader for direct export and prefers an explicitly saved supported preview from the same image result when available; it does not construct proxy URLs or expand host access. These background requests omit cookies, authorization tokens and referrers, reject redirects, validate the image bytes and size, and support cancellation. The downloaded preview bytes are embedded without re-encoding; this does not claim equivalence to the original file offered by ChatGPT's Download button. Failure to download one of these previews stops the export with an explanation. Other images that cannot be embedded by the page collector may retain an external reference with a notice, so opening that export can request the image from its original host. Embedded images are self-contained.
